# `update-third-parties` — design notes

> **Maintainers only.** This file is **not** loaded by the Claude Code skill loader — only `SKILL.md` is ingested when the skill is invoked. Keep operational instructions in `SKILL.md`; keep rationale here.

Adapted from `workleap/wl-app` (`.claude/skills/_update-third-parties`). This repo has no Intent UI and no e2e suite, so the orchestrator covers two targets and the deps leaf owns its own follow-ups.

| Decision | Choice | Why |
|---|---|---|
| Orchestrator model | `model: sonnet` | The orchestration is mechanical — prompt, dispatch, aggregate — so opus is wasted, but it must compose leaf briefs and merge reports; haiku under-serves that. Right-first-time tiering: a botched brief or dropped report line is a silent miss. |
| Leaf model and effort in the table | Each `Agent` leaf is dispatched at the table's model and effort; `_update-skills` mirrors its values in frontmatter, `_update-dependencies` declares none | A skill's `model:` is ignored inside a leaf — the dispatch sets it — while its `effort:` overrides the dispatch's, so any copy must stay identical. Inline `Skill` invocation would switch the *conversation* model per delegate and leave it on the last one; delegation confines each skill to its leaf. Unlike wl-app's, this repo's deps skill migrates breaking changes and validates sample apps in a browser — so its leaf runs on opus/high, and the skill carries no `model:` override that would downgrade a direct `/_update-dependencies` session. |
| Decisions hoisted to one up-front prompt | The orchestrator asks targets + deps follow-ups once; leaves are briefed to never prompt (deps: run the follow-ups it's given) | Leaves can't reach the user mid-run. The user still walks away after one prompt. |
| Follow-ups run inside the deps leaf | Reset + install and validate are passed to `_update-dependencies` instead of running in a separate runner leaf after the last target (wl-app's shape) | Here "validate" is not a verbatim relay like wl-app's `pnpm e2e-test`: it drives three sample apps in a browser, triages console output against an ignore list, and migrates or reverts packages on breaking changes — all deps-skill knowledge. Skills are docs and never affect the build, so validating before the skills update loses nothing. |
| Sequential targets | deps -> skills, never parallel | `_update-skills` gates each skill on its package being on the latest minor; it must see the bumped versions, and both contend on the pnpm store. |
| Skill installs re-pulled with `skills add`, not `skills update` | Each `_update-skills` row carries an explicit `skills add <source> --skill <name> -a … --copy -y` | `skills update` refuses entries installed before the CLI tracked `skillPath` (all of this repo's, initially). `-a codex` keeps the install in `.agents/skills` only; `claude-code` is added only where a `.claude/skills` copy exists today; `--copy` avoids the CLI's default absolute-path symlink. |
